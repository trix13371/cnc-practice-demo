Продолжение [аудита](AUDIT-20261103.md) и [исправлений P1](P1-FIXES-20261103.md). Изменения проверяются на локальном стенде; Beget не обновляется.

## Старт курса

Учебные JS-исходники собираются в памяти при запуске сервера в три пакета: bootstrap хранилища, модели и интерфейс. Список и порядок модулей берётся из той же `index.html`, что используется автономной версией. Bootstrap устанавливает отдельное хранилище аккаунта, модели разбирают локальные/серверные сохранения, и только после восстановления запускается интерфейс. Переносы прогресса, конфликты и откат ревизий сохраняют прежнюю семантику. Записи на read-only filesystem и npm-зависимости не добавлены.

Имена пакетов содержат хеш содержимого. Сессия проверяется до выдачи ресурса или 304; API и личные HTML сохраняют `no-store`. Каждый новый процесс создаёт пакеты из своих исходников. Запрос отсутствующего пакета старого выпуска завершается 404; загрузчик предлагает перезагрузку и не отправляет частичный архив. Открытая автономная версия продолжает использовать исходные модули.

Измерения до/после на одних исходниках и при одинаковом gzip level 6:

| Метрика JS для старта курса | До | После |
| --- | ---: | ---: |
| Запросы, включая account-client | 73 | 4 |
| Сумма исходных байт | 1 356 873 | 1 359 369 |
| Сумма gzip-байт | 440 373 | 366 589 |

Снижение расчётного gzip-объёма — около 17%. Небольшой рост исходного текста связан с разделителями и подписями файлов в пакетах. Число подключённых JS подтверждено реальным DOM до и после локального обновления. Gzip-числа — воспроизводимый расчёт файлов, не сетевой замер Caddy. В production Caddy уже выполняет сжатие; локальный Node HTTP не выдаёт gzip.

Это оптимизация числа запросов и сжатого объёма, а не заявление о достижении определённых LCP/INP на мобильной сети. Все разделы пока загружаются при старте; отложенная загрузка необязательных экранов остаётся отдельной работой.

Проверки: три фазы покрывают исходники ровно по одному разу, порядок сохраняется, пакеты проходят проверку синтаксиса, bootstrap/модели исполняются в отдельном VM-контексте, хеши стабильны для одинакового содержимого. Серверные проверки подтверждают авторизацию, ETag/304 и отказ для неизвестного пакета. Проверены сбои каждой фазы без серверной записи и без запуска синхронизации, изоляция аккаунта, импортированный черновик и конфликт вкладок. `npm test` (46 групп), `npm run test:server` (7 групп) и `node scripts/check-build.cjs` прошли.

В браузере после обновления восстановлено занятие 2/9, открылись мастерская и G-код, ошибок консоли на проверенных переходах нет. На узком viewport 320 px (305 px доступной ширины со скроллбаром) проверенные экраны не переполняют документ по горизонтали. Малые области касания навигации/раскрывающихся заголовков остаются отдельным пунктом P3; полная мобильная и клавиатурная приёмка не заявляется.

Перед обновлением сохранена проверенная копия `/data/before-p2-fixes-20261103.sqlite` в локальном data volume. Инструменты, промежуточные метрики и запрос OpenRouter находятся вне репозитория в каталоге разработки.

## Отчёт администратора

Технические ID диагностических, токарных и фрезерных заданий заменены в интерфейсе их названиями. Причины диагностики и коды фрезерных блокировок показываются человеческими подписями из исполняемых моделей, без отдельного дублирующего справочника. Для старой неизвестной записи есть понятная подпись о недоступном описании. В сводке видны блоки с проверками, завершившимися ошибкой, и открывавшимся разбором; данные относятся к текущим попыткам. Намеренная диагностика не объявляется автоматически ошибкой ученика.

`server/admin-report.cjs` добавляет только поля представления в ответ администратора. Исходные коды и ID остаются в журналах и экспорте; чтение отчёта не меняет архив, сохранённую сводку или ревизию. Названия всегда вставляются как текст. Роли, проверки сессии и доступ только администратора к чужому прогрессу сохранены.

Проверены реальные учебные журналы диагностики/фрезерования, подписи причин, неизвестные старые коды, отсутствие мутаций и вывод ошибок в верхней сводке. API-тест проверяет подписи и неизменность экспортируемого архива; UI-тест использует воспроизведённую попытку с ошибкой и её исправление. После этого изменения прошли все 8 серверных групп и проверка сборки; основные 46 групп прошли на предыдущем шаге без изменений учебных моделей. Локальный Docker пересобран, app/backup здоровы, страница администратора открыта в браузере без ошибок консоли.

Дополнительный запрос tester-модели через OpenRouter завершился тайм-аутом и не дал пригодного ответа. Независимое заключение модели отсутствует; положительные результаты выше относятся к выполненным тестам и браузерной проверке.

## Что остаётся открытым

- Подгрузка необязательных экранов по требованию и замер LCP/INP на ограниченной сети. Текущая сборка сокращает запросы, но пока загружает все семейства интерфейса.
- Полная мобильная и клавиатурная приёмка, включая малые области касания, — отдельный пункт P3. Проверенные узкие экраны не заменяют такую приёмку.
- Расширение технологического охвата курса и предметная проверка нормативных оснований остаются этапами развития. РФ-7 по договорённости идёт после функциональных работ; соответствие ГОСТ здесь не объявляется.
