# CSS: источники и границы ответственности

Редактируем CSS только в этом каталоге. Корневые `app.css`, `style.css`, `light-theme.css` и остальные старые URL — генерируемые файлы для приложения и совместимости. Дополнительные темы поверх них не подключаем.

- `tokens.css`: единственное место глобальных цветов, размеров текста и шрифтовых переменных.
- `foundation.css`: общие элементы, формы, таблицы и базовые компоненты тренажёра.
- `training.css`: уроки, практикумы, измерения, чертежи и учебные панели.
- `layout.css`: оболочка, навигация, главная и адаптивная компоновка.
- `sandbox.css`: свободная мастерская.
- `machine.css`: панель стойки ЧПУ.
- `account.css`: вход, аккаунт, синхронизация и административные страницы.
- `typography.css`: общий шрифт, типографика и масштабирование текста; используется также автономными страницами входа и администратора.

После правки: `npm run build:styles`. Затем `npm test` и проверка затронутого экрана в браузере, включая мобильную ширину. `npm run build:demo` собирает CSS перед созданием автономной страницы. Docker также собирает CSS из этих источников. CI проверяет, что генерируемые файлы совпадают с источниками.

Правило нового экрана: собственный корневой класс и локальные селекторы в соответствующем файле. Общие значения берём из tokens; общие компоненты изменяем в их источнике. Не исправляем локальную проблему очередным глобальным правилом для `button`, `input`, `.panel` или добавлением файла новой темы. `!important` допустим для существующих инвариантов вроде `[hidden]`, а новые применения требуют объяснения конкретного конфликта.

Во время миграции удалены 517 более ранних деклараций, перекрытых тем же селектором/свойством в том же условном контексте. Порядок оставшихся правил и медиазапросов сохранён. Дальнейшее упрощение отдельных компонентов выполняем отдельно от изменения учебной математики и сохраняемых журналов.
