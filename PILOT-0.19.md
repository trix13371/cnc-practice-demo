# Локальный пилот 0.19

## Запуск для участника

Из каталога проекта выполните `npm start`, затем откройте **http://127.0.0.1:4173/demo/cnc-demo.html**. Это один согласованный адрес локального пилота. Сервер слушает только этот компьютер; публичная публикация не выполнялась. В проекте нет зависимостей, требующих `npm install`; нужен Node.js 18 или новее.

Для обычного занятия откройте «Мой курс» и нажмите начало/продолжение. Обязательный путь — 22 шага. После самостоятельного итога G-кода открывается общая сводка. В любой момент: «Ещё → Результаты».

Перед обновлением или сменой компьютера скачайте «Весь прогресс · JSON». На новом месте откройте результаты, выберите файл, прочитайте сводку переноса и нажмите «Объединить и восстановить». При начатой местной работе её черновики сохраняются; другие подтверждённые истории учитываются в общей сводке. Если занятие ещё не начато, восстанавливается состояние из файла. Разные задачи одного раздела также становятся доступны напрямую. Разные ветки журнала навыков остаются отдельными историями.

Файл `demo/cnc-demo.html` работает автономно. Перенос между ним и адресом сервера выполняйте через JSON: хранилище браузера привязано к адресу. `localhost`, `127.0.0.1`, другой порт и другой профиль браузера могут иметь разные сохранения. Архив включает ответы и историю обучения; участники хранят свои файлы отдельно.

«Сводка · TXT» предназначена для чтения преподавателем и не заменяет восстанавливаемый архив. Предыдущая копия появляется после переноса: сначала её можно просмотреть, затем восстановить все разделы. Перед восстановлением создаётся новая предыдущая копия, поэтому возврат тоже обратим.

На общем компьютере используйте отдельный профиль браузера для каждого участника. Объединение предназначено для продолжения обучения одного человека, а не для сложения результатов группы. Пока нет серверной идентификации, подписей результатов и сертификатов.

## Повторяемая техническая проверка

1. `npm test` — 18 наборов, включая связанные результаты 22 шагов, сохранение конфликтующих веток, прогноз без зачёта из разных веток, повреждённый импорт и транзакционные сбои.
2. `npm run build:demo` и `npm run build:handbook`.
3. `node scripts/check-build.cjs` — синтаксис 37 подключаемых модулей, наличие встроенных ресурсов и версии обеих сборок.
4. `node scripts/build-qa-fixtures.cjs` — создаёт отдельную временную папку с `local.json`, `full.json`, `corrupt.json`. Это служебные решения для проверяющего, не задания участника.

Для ручной проверки запустите два сервера с разными значениями переменной `PORT`, например 4190 и 4191. На Windows: в отдельном PowerShell `$env:PORT='4190'; npm start`. На Linux/macOS: `PORT=4190 npm start`. Эти адреса используются только для QA, пользовательский основной профиль не очищать.

На чистом тестовом адресе откройте результаты. Импортируйте `local.json`: должно быть 1/22, местный X29 и черновик программы с помощью. Затем импортируйте `full.json`: 22/22, оба самостоятельных итога, 2 прочитанные статьи и 2 экзамена. Местный черновик G-кода и помощь должны сохраниться. Повторный импорт того же файла не увеличивает число сохранённых состояний. На второй вкладке старого состояния после переноса появляется требование перезагрузки.

Проверьте `corrupt.json`: импорт отклонён целиком, после перезагрузки остаётся 22/22. Откройте предыдущую копию до первого объединения: предпросмотр должен показать 22→1; после восстановления — 1/22 с прежними черновиками. Новая предыдущая копия позволяет вернуть 22/22. Затем скачайте JSON через интерфейс и импортируйте на второй чистый адрес: результаты, прогнозы, контроль и альтернативные состояния должны сохраниться. Скачайте TXT и сравните с интерфейсом.

Сбои записи и прерывание транзакции воспроизводятся автоматическими тестами с хранилищем, которое отказывает на выбранной операции. Ручной браузерный прогон не имитирует отключение питания. При настоящем сбое записи сохранённый журнал восстанавливается до запуска контроллеров. Если журнал повреждён, обучение блокируется без очистки данных и предлагается доступная диагностическая копия.

Подготовлен `.github/workflows/checks.yml`: тесты и обе сборки будут запускаться после отправки изменений на GitHub. Удалённый запуск CI в этой итерации не выполнялся. Подход к запуску Node.js взят из [официальной документации GitHub Actions](https://docs.github.com/en/actions/tutorials/build-and-test-code/nodejs).

## Ограничения перед наблюдениями за новичками

Общий файл ограничен 4 МБ, для раздела сохраняется до 40 разных альтернативных состояний. При достижении лимита перенос отклоняется, старые данные не обрезаются. Для транзакции дополнительно нужно место в хранилище браузера. Внешние ссылки требуют интернета, само обучение и справочник встроены в HTML.

Общая сводка показывает лучшие подтверждения по сохранённым историям. Последняя тренировка может требовать повторения даже при историческом зачёте. Старые базовые зачёты без журнала действий отмечаются как исторические; новая самостоятельная обработка и итог G-кода требуют воспроизводимого подтверждения на других условиях. Это учебная самопроверка внутри модели.

Проведён внутренний прогон в настольном встроенном браузере. Отдельный прогон на телефоне и целевых компьютерах учебной площадки ещё нужен. Следующий этап E — проверить содержание с преподавателем, наблюдать за новичками без подсказок по интерфейсу и провести отложенное задание.
