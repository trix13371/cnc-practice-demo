# Проверка безопасности беты — 26 октября 2026

Объект: исходники CNC Practice 0.21, Docker-конфигурация и собственный VPS Beget 159.194.227.193. Проверка кода, автоматические регрессионные тесты, сканирование образов Trivy 0.76.1 и ограниченные проверки опубликованного HTTPS API. Нагрузочные атаки и подбор реальных паролей участников не выполнялись.

## Подтверждённые проблемы и исправления

### Дорогая проверка прогресса блокировала HTTP-процесс

Архив менее 200 КБ с допустимой историей из 10 000 действий раздела навыков не завершал синхронную проверку за 6 секунд. Лимит размера запроса эту проблему не предотвращал. В старом обработчике пользователь с действующим аккаунтом мог занять основной поток сервера повторным проигрыванием истории и задержать запросы остальных участников.

Валидация, воспроизведение истории, вычисление итогов и хешей перенесены в отдельный Node worker. Одновременно работает один worker, в очереди не более двух запросов. Лимиты worker: 2 секунды, 64 МиБ old generation, 16 МиБ young generation и стек 4 МиБ. Превышение сложности возвращает 422, занятая очередь — 503. Ни частичный прогресс, ни неподтверждённые итоги в SQLite не записываются. Локальная копия остаётся в браузере.

Регрессия проверяет таймаут, ограничение очереди, доступность HTTP во время дорогой проверки, отсутствие частичной записи и успешное сохранение обычного архива после остановки worker. На Windows контрольные запросы занимали до 18 мс, в Linux-контейнере — до 15 мс. При ограниченной проверке публичного HTTPS API получены 36–41 мс; тяжёлый архив получил 422, версия сохранения не изменилась. Это результаты конкретных коротких проверок, а не обещание производительности под DDoS.

### Первоначальный файл выдачи паролей оставался в контейнере

После инициализации /data/initial-access.private.json больше не нужен приложению. Файл был недоступен через HTTP, но его присутствие рядом с базой увеличивало последствия потенциального чтения файлов из контейнера.

Содержимое сверено с уже выданной организатору закрытой копией. Файл перенесён за пределы контейнеров в /root/cnc-beta-secrets/initial-access.private.json, владелец root, права 600, каталог 700. Локальная копия организатора сохранена; пароли пользователей не менялись. Инструкция развёртывания дополнена удалением файла выдачи из контейнера после получения защищённой копии.

### Обновления безопасности ОС и базовых образов

Установлены доступные обновления безопасности Ubuntu через штатный unattended-upgrade. В том числе OpenSSH 10.2p1-2ubuntu3.8, OpenSSL 3.5.5-1ubuntu3.7 и пакет ядра 7.0.0-38.38. Автоматические обновления безопасности были включены и оставлены включёнными. VPS перезапущен: uname подтверждает 7.0.0-38-generic, признака reboot-required нет, контейнеры запустились автоматически, app и backup healthy. После перезапуска повторно проверены доступ по SSH-ключу и правила firewall.

Рабочий Node обновлён с 24.21.0 до 24.22.1: это выпуск с исправлениями безопасности от 21.10.2026. Приложение не использует сторонние npm-зависимости. Ненужные npm, npx и yarn удалены из рабочего образа; сборка и тесты исходников выполняются на машине разработки/CI, а команды внутри контейнера используют node.

Официальный доступный образ Caddy 2.11.7 содержал старый Go и библиотеки с записями CVE. Добавлен Dockerfile.proxy: тот же выпуск Caddy собран Go 1.27.3 с golang.org/x/net 0.60.0 и chi/v5 5.4.0; финальный Alpine 3.24.3 содержит только бинарник, CA и часовые пояса. Исходные модули проверяются стандартной checksum database Go; итоговые go.mod/go.sum сохранены в образе /usr/share/cnc-proxy/. Этот отдельный образ нужно поддерживать и пересобирать при следующих обновлениях безопасности.

Результаты Trivy — количество записей, не уникальных CVE:

| Образ | HIGH до | MEDIUM до | LOW до | После исправления |
|---|---:|---:|---:|---|
| Приложение | 5 | 9 | 1 | Замечаний сканера нет |
| Прокси | 8 | 16 | 45 | HIGH/MEDIUM/LOW нет; 1 UNKNOWN |

CRITICAL в этих сканированиях не было. Оставшаяся запись GO-2026-5932 относится к неподдерживаемому пакету golang.org/x/crypto/openpgp. Проверен полный список импортируемых пакетов собранного Caddy: openpgp в него не входит. Это предупреждение о модуле, а не подтверждённый доступный путь атаки текущей сборки. Оно оставлено в исходном отчёте, а не скрыто фильтром. При изменении состава модулей прокси нужна повторная проверка.

Дополнительно: Caddy переведён на файловую систему только для чтения, сброшены Linux capabilities, оставлен NET_BIND_SERVICE. Временные разделы помечены noexec/nosuid/nodev. Docker-журналы всех трёх сервисов ограничены 3 файлами по 10 МБ для предотвращения неограниченного роста диска.

## Что проверено без обнаружения обхода

- Семь разных аккаунтов, scrypt с индивидуальной солью; API не возвращает пароль или его хеш.
- Сессии с криптографическим случайным токеном; в SQLite хранится его SHA-256. Secure/HttpOnly/SameSite=Strict и префикс __Host- в HTTPS. Выход отзывает сессию, проверяются срок и неактивность.
- CSRF-токен и точный Origin для операций изменения. Запрос с чужим Origin отклонён на публичном сервере.
- Серверная проверка роли; обычный участник не получает админку и чужой прогресс. userId из query не выбирает владельца сохранения. Отдельные резервные копии доступны только владельцу.
- Параметризованные SQL-запросы; отсутствие выполняемого пользовательского SQL и команд оболочки в HTTP-обработчиках.
- Ограничения подбора паролей по аккаунту и IP сохраняются после перезапуска. X-CNC-Client-IP принимается только от явного адреса прокси, сам Caddy перезаписывает входящий заголовок.
- Лимиты тела запроса, числа читаемых тел и размера архива; строгая проверка структуры, глубины, неподдерживаемых полей и prototype pollution.
- Проверка revision и mutationId предотвращает незаметное перетирание другой версии и повторную запись того же запроса.
- Текстовые заметки и пользовательские строки в интерфейсе выводятся через textContent. Просмотрены места innerHTML: статические шаблоны либо геометрия из числовых/экранированных значений. CSP запрещает inline scripts и встраивание страницы.
- Статическая раздача использует явный список. С действующей сессией .env, .git/config, SQLite, исходники сервера, файл выдачи паролей и файлы резервирования через HTTPS возвращают 404.
- Поиск семи действующих серверных паролей в 50 публичных файлах исходников: совпадений нет.
- Приложение работает как node с read-only rootfs, без capabilities и без публикации 8080. Внешние проверки 8080 и 2019 не нашли открытого сервиса; слушатели VPS — SSH, HTTP и HTTPS, DNS только loopback.
- SSH-ключи работают, PasswordAuthentication и KbdInteractiveAuthentication отключены; UFW включён, частота SSH ограничена.
- Проверены целостность резервной SQLite-копии, права закрытых файлов и отдельная копия базы на компьютере организатора.

## Практические ограничения

Это аудит конкретной версии, а не гарантия отсутствия уязвимостей. Нужны регулярные обновления ОС, Node и прокси и повторные сканирования. Защита от распределённого сетевого DDoS требует возможностей площадки/CDN; приложение её не заменяет.

sslip.io — сторонний временный DNS. Для постоянного запуска желательно собственное доменное имя и контроль регистратора/DNS. Администратор пока без MFA, регистрация закрыта. Перед увеличением группы нужны управление аккаунтами и индивидуальная выдача доступа.

Учебные итоги пересчитываются по присланной истории, но история формируется на устройстве участника. Подготовленный пользователь может сформировать правильный журнал программно. Эта бета подходит для обучения и наблюдений; она не доказывает личность и самостоятельность сдающего для официальной сертификации.

Автоматические резервные копии пока находятся на том же VPS; отдельные проверенные копии скачаны вручную. Для длительной беты нужно автоматическое резервирование вне VPS и проверка восстановления.
