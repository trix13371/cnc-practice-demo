# Т09–Т10: диагностика причины и самостоятельное изделие

Основание: пользователь одобрил объединённую реализацию этапов 09–10. Учебная модель остаётся изолированной от физического оборудования. Мастерская не получает обязательных подсказок курса.

## Границы модулей и порядок

| Модуль | Ответственность | Зависимость |
| --- | --- | --- |
| Первая отказавшая строка | Производный кадр проверки: исходное положение, координаты, команда, инструмент, G54 и отказ | Существующий real-machine-model |
| Диагностическое расследование | Исходная и исправленная проверки, визуализация отвергнутого движения, чтение причины | Кадр + существующий diagnostic-course-model |
| Самостоятельный проект | Пятый фиксированный чертёж, пустой редактор, дополнительные черновые переходы, документы и текущий контроль | Существующий shaft-project-model и реальное исполнение |

Реализовать в этом порядке. Повторное согласование уже одобренных Т09–Т10 не требуется.

## Т09

- Для десяти существующих задач показать исходный отказ отдельно от последней проверки исправления. Не заменять исходные условия отредактированным текстом.
- Для X/Z выводить фактическую строку программы, положение перед отказом, заданный конец движения, G54, инструмент, вращение и код отказа. Рабочие и физические координаты подписывать отдельно.
- Для XYZ выводить первую отвергнутую строку маршрута, движение целиком, затронутую часть сборки/препятствие и проекции XY/XZ. Цвет сопровождать текстом.
- Отвергнутый отрезок не объявлять выполненным. Точную точку контакта не выдумывать; поле контакта показывать только если движок действительно его вычислил.
- Исправление принимается прежними проверками причины, наладки, результата и полного пути. G54=98 нельзя компенсировать сдвигом всех координат, обход должен проверять весь путь, а не только конец.
- Старые журналы воспроизводятся без новых обязательных событий; повреждённая запись не заменяется новой. Новая визуализация не считается новым доказательством ранее не выполненного действия.

## Т10

- Новый фиксированный проект RF5-SHAFT-05: заготовка Ø38, вылет 74, зажим 15; A Ø30 длина22, B Ø33 длина26, C сохраняется38; справочный reach48. Диаметры ±0,10, основные длины ±0,20 мм.
- Редактор новой работы пустой; четыре прежних проекта и их каркасы не изменяются. Полное решение не подставляется в интерфейс.
- Радиальный съём T0101 до2мм: общий Ø33 изØ38 сразу недопустим. Доступны дополнительный общий черновой Ø35 и предварительный проход передней шейки Ø35.
- Принимаются минимум два технологически различных допустимых порядка переходов. План проверяется на копии; зачёт требует исполнения на собственной виртуальной заготовке.
- Чертёж, лист наладки, карта контроля и критерии выпуска выводятся из канонических task/rows. Документ docs/project-shaft.json генерируется, не хранит вторую независимую копию требований.
- Обязательны свежие записи всех диаметров и длин, включая вычисляемую длину B, и сравнение плана с фактическими переходами. Скорость и число попыток не компенсируют пропущенный контроль.
- Курс получает один новый шаг; исторические 22/51/57/63-шаговые результаты не дают его автоматически. Портфели v1/v2 продолжают читаться. Не менять записи реальных участников тестовыми результатами.

## Проверки и выпуск

Сначала отрицательные тесты кадра/неполного контроля/неверного нуля, затем реализация. Проверить альтернативный план, чрезмерный съём, устаревшую программу и замер, сохранение, неизвестные метаданные и неизменность исходного объекта.

Команды: `npm test`, `npm run test:server`, сборки demo/handbook/model-spec/normative/curriculum, `node scripts/check-build.cjs`. Полный маршрут с четырьмя историями должен уложиться в прежние2сек worker в контейнере1CPU/512MB. Пределы журналов и ресурсов не повышать для получения зелёного теста.

В браузере проверить исходный G54-отказ и исправление, XYZ-державку/колонну, пустой новый проект, выбор маршрута, документы, измерение и продолжение после перезагрузки. Подписи/выноски однозначны; ошибки рядом с действием. При обнаружении неоднозначности сохранить и показать пользователю скриншот.

Обновление только локального Docker после проверенной резервной копии. Ключ OpenRouter и инструменты разработки остаются вне репозитория. Новые зависимости, внешняя публикация и изменение физической модели резания не входят в пакет. Предметная сверка ГОСТ Т04 остаётся открытой.
